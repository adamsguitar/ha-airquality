## Air Quality UI (add-on)

This release is a full visual overhaul of the add-on UI plus a redesign of the threshold profile editor.

### Refreshed UI

- New design-token palette with light and **prefers-color-scheme: dark** variants — HA's dark mode now flows through ingress correctly.
- Stronger text contrast (targets WCAG AA), focus-visible rings on all inputs and buttons, and a more consistent component system (primary / secondary / ghost-danger buttons, banners with semantic borders, pill chips for area ids and floor labels).
- Sticky condensed top bar with active-link highlighting; content max-width raised to 1280 px with fluid `clamp()` gutters so wide screens stop wasting space.
- **Responsive room grid** (`auto-fill, minmax(28rem, 1fr)`) — multiple rooms per row on wide screens, single column on phones.
- Slot grid uses `auto-fill, minmax(20rem, 1fr)` so measurement cards always fill the available width.
- Tidied room-card layout (cleaner header with floor and area-id pills) and slot cards (denser, with truncating monospace entity ids).

### Threshold editor

- Each measurement is now a **single line**: a colored band strip with draggable handles plus 4 inline number inputs in logical order (`good → fair → poor → unhealthy` for simple measurements, `fair_min → good_min → good_max → fair_max` for ranges).
- **Monotonicity is enforced in the UI**: a more-severe threshold can never be set to a lower value than a less-severe one. Typed numbers are clamped to neighbour bounds; dragging a handle past a neighbour pushes that neighbour along by the smallest amount needed; arrow keys / Home / End on focused handles work the same way.
- A submit-time guard catches any payload that somehow still violates ordering. The server-side validator is unchanged and remains as defence in depth.

No backend, schema, or service changes; no new dependencies. Reload the integration or refresh the UI after upgrading.
