# v0.6.0

Major UX overhaul focused on per-room devices and an area-driven editor.

## Integration

- One Home Assistant device per configured room, automatically bound to the
  matching HA area. Each measurement is an entity on that device, and the
  per-measurement health band is exposed as the `health` state attribute on the
  measurement entity.
- The composite "Overall" sensor for each room now exposes an
  `unhealthy_reasons` attribute listing the measurements driving a problem
  state (with their values and health bands). Floor and Home rollups expose the
  same attribute, naming the spaces or floors causing the problem.
- Removed the per-measurement health enum sensor and the per-slot opt-in
  problem binary sensor — both duplicated information now available as
  attributes. The `expose_problem_binary` slot field is gone from the schema.
- New service `airquality.get_ui_state` returns areas, candidate AQ sensors per
  area, the current YAML config, and the available measurement list. Used by
  the add-on UI.
- Added explicit area-binding of room devices via the device registry, on top
  of `suggested_area`, so the binding survives version upgrades.

## Add-on

- The add-on is no longer a YAML editor. It now presents an area-driven UI:
  every Home Assistant area appears as a card with controls for adding
  measurement slots, attaching/removing source sensors from drop-downs of
  candidate sensors in that area, choosing aggregation, and picking a
  threshold profile.
- Each mutation persists straight to `/config/airquality.yaml` and reloads the
  integration. Power users can still edit the YAML directly on disk if they
  prefer.
- Discovery is preserved as a "merge proposal into config" flow with an
  optional overwrite mode.
- New "Threshold profiles" page lists the configured profiles and lets you
  delete them (creating/editing thresholds remains in the YAML for now).

## Breaking changes

- Per-slot health enum sensors (`sensor.<area>_<measurement>_health`) and
  per-slot problem binary sensors (`binary_sensor.<area>_<measurement>_problem`)
  are removed. The information is exposed via attributes on the value sensor
  and the per-room problem binary sensor.
- `expose_problem_binary` is no longer a valid slot field. The schema rejects
  it. Remove the field from your YAML if present.
