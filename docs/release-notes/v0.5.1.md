# v0.5.1 — first public release

A sensor-agnostic air quality framework for Home Assistant: define spaces, bind your existing sensor entities, get aggregated values, health bands, and rollups with no per-manufacturer plumbing.

## What you get

**Integration** (`custom_components/airquality/`)
- YAML-driven configuration at `/config/airquality.yaml`, validated against a JSON Schema
- Spaces bound to HA areas (hard requirement, no floating spaces)
- 7 aggregation strategies for combining multiple sensors per measurement: `single`, `average`, `median`, `min`, `max`, `weighted_average`, `primary_with_fallback`
- Threshold profiles with single-inheritance (`extends:`) — pollutant breakpoints (PM, CO₂, VOC, NO₂, O₃) and comfort ranges (temperature, humidity)
- Health bands per slot: `good`, `fair`, `poor`, `unhealthy`, `hazardous`, plus `stale` and `unavailable`
- Worst-state rollup at slot → space → floor → home, ignoring stale/unavailable inputs unless all are
- Per-slot value sensor + health enum sensor; per-space, per-floor, and home composite sensors with all measurements in JSON attributes
- Per-space, per-floor, and home `binary_sensor` of `device_class: problem`. Per-slot binary sensor opt-in via `expose_problem_binary: true`
- Services: `airquality.reload`, `airquality.recompute`, `airquality.set_threshold_profile`, `airquality.discover`
- Auto-discovery: `airquality.discover` scans the entity/device/area/floor registries, classifies sensors by `device_class` + unit (handles both VOC variants, disambiguates °F/°C), filters stale/disabled/hidden, returns proposed YAML
- Diagnostics download (full state snapshot), Repairs integration (slot unavailable / stale / missing profile, auto-resolving), System Health card

**Add-on** (`addon/`) — optional, installable from the same repo URL via the Add-on Store
- FastAPI + HTMX + Jinja2 served behind HA ingress
- Overview of configured spaces and slots
- Discovery wizard with unified diff preview before apply
- Raw YAML editor with schema validation
- ruamel.yaml round-tripping preserves comments and formatting
- Calls `airquality.reload` automatically after each save

## Installation

### Integration via HACS

1. HACS → Integrations → ⋮ → Custom repositories
2. Add `https://github.com/adamsguitar/ha-airquality` as an **Integration**
3. Install "Air Quality" and restart HA
4. Settings → Devices & Services → Add Integration → Air Quality

An example `airquality.yaml` is created on first run. Edit it, then call `airquality.reload`.

### Add-on (optional)

1. Settings → Add-ons → Add-on Store → ⋮ → Repositories
2. Add `https://github.com/adamsguitar/ha-airquality`
3. Install "Air Quality UI" and start

## Known limitations / next up

- Brand assets are placeholder PNGs. The integration card icon won't render until the brand is submitted to `home-assistant/brands`. The integration is fully functional without it.
- Add-on UI is functional but minimal — raw YAML editor for hand-editing; richer per-slot editing is not yet implemented.
- VOC discovery only accepts the `volatile_organic_compounds_parts` (ppb) device class; µg/m³ VOC sensors are skipped with a clear reason.
- Per-measurement weighting in the home rollup isn't implemented; rollup is straight worst-state.

## Requirements

- Home Assistant 2025.1.0 or newer
